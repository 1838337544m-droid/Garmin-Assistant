# 多运动能力处方设计

日期：2026-11-19（Asia/Dubai）

## 意图

将目前只面向“明天能否跑步、10 km 60 分钟”的恢复筛查，升级为可解释的能力处方。使用者设定长期主项和目标；每次分析选择当天项目。系统据此生成当天的运动处方，并明确今天在发展、维持或保护的身体能力。

这不是医学放行、伤病预测器、运动表现保证或自动训练计划。所有建议均须保留数据缺口、主观症状和跑前复评的边界。

## 范围与非目标

第一期原生支持：跑步、骑车、游泳、攀岩。

“其他”可作为当天项目/交叉训练记录，但只返回通用恢复或低风险活动建议，明确“不生成专项强度、技术或负荷规则”。

不在本期内：自动修改训练计划、追踪装备或路线、运动技术诊断、攀岩等级预测、游泳配速预测、跨项目训练等效换算、医疗建议、自动接入第三方平台。

## 已考虑方案

1. **长期主项驱动能力周期 + 当天项目执行（采用）**：长期主项确定目标和能力语言；当天项目决定处方。交叉训练可服务主项，但不能被误称为主项专项刺激。兼顾专业性与多项目现实。
2. 多项目完全平权：每个项目都有独立目标与周期。对真正多项竞技有用，但设置、数据需求和解释复杂度超出第一期。
3. 主项固定、当天项目只是备注：实现简单，却无法为骑车、游泳或攀岩提供可靠差异化处方。

## 用户流程

1. 使用者保存 `athlete_profile`：`primary_sport`、长期目标的自由文本、可选目标日期与经验/能力描述。主项可随时更改，变更时不删除历史报告，但新报告需标注生效配置。
2. 为明天分析时传入 `session_sport` 与可选 `session_intent`（恢复、基础、质量、技能、未指定）。若未提供当天项目，默认等于长期主项；明早仍需同步并复评后执行。
3. 先执行现有同步、数据完整性和症状安全筛查。红旗或信息不足优先于任何专项处方。
4. 由“主项能力模型”说明训练周期要服务的能力；由“当天项目模块”生成项目化建议、剂量边界与降级动作。
5. 报告首屏按顺序呈现：今日行动、能力处方总结、处方依据、未知项/安全边界、项目指标与研究来源。

## 处方模型

### 共同安全门

现有胸痛、晕厥、疾病、步行痛、局部骨痛、疼痛评分、疲劳、同步完整度、睡眠/HRV/静息心率筛查继续优先。任何阻断或关键缺项均禁止输出质量训练；不能因为换到骑车/游泳/攀岩就绕过症状门。

### 长期主项的能力字典

| 主项 | 主要能力 | 首期可处方的保守表达 |
|---|---|---|
| 跑步 | 有氧耐力、阈值耐受、跑步组织耐受、跑步经济性 | 轻松跑/恢复、基础耐力、仅在安全门放行时的质量候选 |
| 骑车 | 有氧耐力、持续功率耐受、踏频/技术、下肢负荷管理 | 轻松转腿、耐力骑、仅在安全门放行时的质量候选 |
| 游泳 | 有氧耐力、技术效率、呼吸节律、肩部耐受 | 轻松技术游、低强度连续游、仅在安全门放行时的质量候选 |
| 攀岩 | 技术与动作质量、指/上肢肌腱耐受、拉力与核心、全身恢复 | 技术/低强度攀爬、休息或非专项恢复；不从 Garmin 数据推断指力或肌腱准备度 |

“质量候选”不是自动批准的质量课。专项负荷、近期训练史、主观检查和足够项目数据均不足时，降级为轻松或恢复。

第一期的质量候选仅允许跑步，且继续采用现有的跑步恢复门、主观检查和最少近期跑步记录要求。骑车、游泳、攀岩仅返回 `avoid`、`recover`、`easy` 或 `base`，不以可穿戴数据批准专项高强度。后续若要开放质量候选，必须先为该项目补充已核验研究、最小同项目历史标准和对应测试。

### 当天项目处方

每个模块输出统一字段：

- `prescription_status`：`avoid`、`recover`、`easy`、`base`、`quality_candidate`；
- `session_action`：清晰的一句话行动；
- `dose`：时长/主观强度/RPE，不臆造配速、瓦数、泳速、攀岩等级；
- `capacity_focus`：发展、维持或保护的能力及理由；
- `downgrade_rule`：出现何种症状或热身反馈时改为何种更低风险行动；
- `evidence_boundary`：数据不能说明什么。

已有 Garmin 原始活动只在能够明确识别项目时用于该项目的近期频率/时长/负荷摘要。不能可靠分类、缺少数据或跨项目时必须标记未知，不进行“等效训练量”换算。

## 数据与接口设计

新增本地、无敏感凭据的配置文件 `%LOCALAPPDATA%/GarminLocalMCP/athlete_profile.json`，只包含使用者主动提供的运动偏好与目标，不复制健康原始数据。写入使用原子替换；`primary_sport` 为规范枚举、`goal` 非空、日期为 ISO 日期、备注长度受限，并存储 `schema_version` 与 `profile_effective_at`。

新增 MCP 工具：

- `garmin_get_athlete_profile()`：读出当前运动配置；
- `garmin_set_athlete_profile(primary_sport, goal, goal_date?, experience_note?)`：写入用户确认的配置；
- `garmin_assess_session(session_sport?, session_intent?, subjective?, refresh_research?)`：替代仅跑步命名的明日评估；默认当天项目为主项；同步、保存 JSON/Markdown 报告。

为了兼容现有工作流，`garmin_assess_tomorrow` 在第一期保留，内部调用新流程并显式传入跑步；它保留完全相同的参数、返回字段、报告命名与跑步语义，现有调用不会静默改成其他项目。除 `garmin_set_athlete_profile`（非破坏性本地设置写入）外，所有 Garmin 数据工具继续标记为只读；菜单和服务说明要如实反映此例外。

配置和报告应包含 `schema_version`、`primary_sport`、`session_sport`、`session_intent` 和 `profile_effective_at`。每份新式报告使用目标日期、当天项目和生成时刻/唯一标识组成的文件名，避免覆盖历史配置下的报告；旧工具在兼容要求明确前保留原报告命名。写入配置是唯一具有状态变化的新操作；所有分析工具继续只读 Garmin 数据。

活动分类在 MCP 参数边界使用规范枚举；Garmin 原始 `typeKey` 映射为稳定的已知类别，无法确认则为 `unknown`，不得猜测。近期频率、较强/较长训练与项目负荷摘要仅使用和当天项目可靠匹配的活动；睡眠、HRV、静息心率、症状和同步完整度为跨项目共享安全门。

## 报告/UI 内容结构

报告不伪造 Garmin/Oura/WHOOP 的专有评分。新的 Markdown/结构化结果使用原创信息层级：

1. `今日训练处方`：项目、行动、剂量、强度边界；
2. `能力处方总结`：主项长期能力、今天是发展/维持/保护、当天项目如何服务它；
3. `处方依据`：可用的 Garmin 信号、项目近期记录、主观检查；
4. `未知与安全边界`：缺失信息、不可推断内容、降级条件；
5. `研究与模型`：仅列出已核验并与该处方相关的来源；未评估候选不成为规则。

日后图形化界面可渲染相同的结构化字段；本期先保证 MCP 返回和 Markdown 报告一致、可读。

## 验收标准

1. 使用者可保存并读取四个主项之一及目标；无配置时分析明确要求设置主项，不猜测。
2. 主项为跑步、当天项目为骑车时，报告能说明骑车服务哪个跑步能力，并且不将其称为跑步专项训练。
3. 四个当天项目均有不同的行动、能力焦点、剂量边界和降级表达；“其他”不会生成专项规则。
4. 红旗、疾病、疼痛、关键数据缺失及未完成同步对所有项目一致优先，且不输出质量训练。
5. 攀岩报告明确 Garmin 数据无法确认指力、肌腱或皮肤准备度。
6. 原 `garmin_assess_tomorrow` 行为与接口保持兼容；现有测试通过，并补充配置、跨项目、各项目和阻断优先级测试。
7. 报告始终含依据、未知/不确定、不能推断、下一步/降级条件与来源日期；不得读取密钥、私人健康数据或配置以外的文件。

## 实现决策留给构建阶段

- Garmin 的活动类型映射仅采用本地缓存已经提供的公开活动元数据；识别不确定时保守降级。
- 首期不宣称任何项目具有已经过个体验证的数值阈值；RPE/谈话测试和明确的降级条件优先。
- 新研究应按项目检索并区分候选与已核验来源；若项目缺乏已核验来源，报告须明确限制而非补造规则。

## 待产品确认

已确认：新通用分析为明天开处方；旧跑步工具保持完全兼容；骑车、游泳、攀岩首期不生成质量候选；游泳新增肩痛与是否独自下水确认，缺失任一信息时不生成游泳专项处方。
